# IOAI 2025 — Past Problems and Advanced Techniques

IOAI 2025 was the second edition of the International Olympiad in Artificial Intelligence. With one year of institutional knowledge accumulated from 2024, both the organizers and participants arrived more prepared. The result: a harder competition with more sophisticated problems, more participants, and a higher skill ceiling required to medal.

This lesson dissects the 2025 competition structure, covers the advanced techniques that became critical, and provides actionable walkthroughs for the two major new task types: NLP classification and computer vision classification.

---

## Section 1: How 2025 Differed from 2024

### Increased Difficulty Calibration

After 2024, organizers had benchmark scores and participant distributions to work with. The 2025 problems were calibrated to reduce ceiling effects: problems where the top 30 participants cluster at 99% accuracy are not useful for discrimination. In 2025:

- Baseline scores were deliberately pushed lower through more challenging preprocessing requirements
- Stronger performance required understanding of evaluation metric nuances
- Neural network and embedding-based approaches became viable and sometimes necessary

### Broader Task Types

2024 was heavily tabular. 2025 expanded the practical exam to include explicit NLP and computer vision components. Students who had only practiced tabular classification were at a significant disadvantage.

### Theoretical Component — Greater Depth

2025 theory questions pushed into:
- Gradient descent variants: SGD, Adam, RMSprop — mathematical derivations and convergence properties
- Transformer architecture: attention mechanism, positional encoding, why transformers outperform RNNs on long sequences
- Advanced regularization: dropout, batch normalization, weight decay — how each works mechanically
- Evaluation traps: AUC-ROC vs precision-recall curves, why AUC-ROC can be misleading on imbalanced data

Sample theory question style from 2025: *"The Adam optimizer maintains per-parameter estimates of the first and second moments of gradients. Derive the bias-correction terms. Why are they necessary in the early iterations of training?"*

This requires not just knowing that Adam uses bias correction but deriving it.

## Section 2: Theoretical Component Deep Dive

### Neural Network Fundamentals You Must Know

Before touching code, you need the theory cold.

**Forward pass:**
Given input x, weights W, biases b, and activation function σ:
```
z = Wx + b
a = σ(z)
```
For a network with L layers, this chains L times.

**Backpropagation:**
The gradient of the loss with respect to any weight is computed by the chain rule, flowing backward through the network. For the output layer:
```
dL/dW_L = dL/da_L * da_L/dz_L * dz_L/dW_L
```
The key insight: gradients multiply together through layers, which is why deep networks can suffer from vanishing or exploding gradients.

**Vanishing gradients:**
When activation functions like sigmoid have derivatives that are < 1 everywhere, gradients shrink exponentially with depth. ReLU (derivative = 1 for positive inputs, 0 otherwise) largely solves this for forward pass but introduces "dying ReLU" — neurons that always output 0 once their gradient is 0.

**Attention mechanism:**
Given queries Q, keys K, values V:
```
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) * V
```
Where d_k is the dimensionality of the keys. The sqrt(d_k) scaling prevents the dot products from becoming too large (which would push softmax into saturation, causing vanishing gradients).

### Bias-Variance in the Context of Deep Learning

The classical bias-variance tradeoff says: more complex models → lower bias, higher variance. Deep learning complicates this with the "double descent" phenomenon: past a certain model size, test loss can decrease again even as training loss continues to fall. This is an active research area; for IOAI purposes, knowing it exists and that regularization (dropout, weight decay, data augmentation) addresses the high-variance regime is sufficient.

### Evaluation Metrics — Advanced Understanding

**AUC-ROC:**
The area under the receiver operating characteristic curve. It measures the probability that the model ranks a random positive example higher than a random negative example. This is threshold-independent but misleading when the positive class is rare (e.g., 1% positive rate), because the "negative" side of the ROC curve is dominated by true negatives.

**Precision-Recall AUC (PR-AUC):**
More informative than ROC-AUC for imbalanced classification. It focuses entirely on the positive class. If you have a 1:99 class ratio and a competition uses PR-AUC, a model that predicts all zeros gets PR-AUC ≈ 0, while it would get ROC-AUC ≈ 0.5.

**Log Loss (Cross-Entropy Loss):**
```python
# Log loss penalizes confident wrong predictions severely
from sklearn.metrics import log_loss
logloss = log_loss(y_true, y_pred_proba)
# A model predicting 0.99 for the wrong class gets penalized ~100x more
# than a model predicting 0.5 for the wrong class
```

If the competition uses log loss, calibrating your model's probabilities (using `CalibratedClassifierCV`) can improve your score even if your raw classification accuracy doesn't change.

## Section 3: NLP Task Walkthrough — Text Classification

Text classification appeared prominently in IOAI 2025. The pipeline follows a clear progression: start with TF-IDF + Logistic Regression, then upgrade to transformer embeddings if you have time and the compute is available.

### Phase 1: TF-IDF Baseline

TF-IDF (Term Frequency-Inverse Document Frequency) converts text to numerical features by scoring each word's importance in a document relative to the corpus.

```python
import numpy as np
import pandas as pd
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.metrics import f1_score, classification_report

# Load data
train = pd.read_csv("train.csv")
test  = pd.read_csv("test.csv")

TEXT_COL = "text"      # column containing text
TARGET   = "label"     # column containing class label

X_train = train[TEXT_COL]
y_train = train[TARGET]
X_test  = test[TEXT_COL]

# Basic text cleaning
def clean_text(series):
    return (series
            .str.lower()
            .str.replace(r"[^a-z0-9\s]", " ", regex=True)
            .str.replace(r"\s+", " ", regex=True)
            .str.strip())

X_train_clean = clean_text(X_train)
X_test_clean  = clean_text(X_test)

# TF-IDF + Logistic Regression pipeline
tfidf_lr = Pipeline([
    ("tfidf", TfidfVectorizer(
        max_features=50000,
        ngram_range=(1, 2),       # unigrams and bigrams
        sublinear_tf=True,         # log(1 + TF) instead of raw TF
        min_df=2,                  # ignore very rare terms
        strip_accents="unicode",
    )),
    ("model", LogisticRegression(
        C=1.0,
        max_iter=1000,
        solver="lbfgs",
        multi_class="auto",
    )),
])

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(tfidf_lr, X_train_clean, y_train,
                          cv=cv, scoring="f1_macro")
print(f"TF-IDF + LR CV F1-macro: {scores.mean():.4f} ± {scores.std():.4f}")
```

### Phase 2: Tuning the TF-IDF Pipeline

Before jumping to transformer embeddings, squeeze more performance from the TF-IDF approach:

```python
from sklearn.linear_model import SGDClassifier
from sklearn.svm import LinearSVC
from sklearn.ensemble import GradientBoostingClassifier

# Try LinearSVC — often stronger than LR on text with TF-IDF
tfidf_svc = Pipeline([
    ("tfidf", TfidfVectorizer(
        max_features=100000,
        ngram_range=(1, 3),
        sublinear_tf=True,
        min_df=2,
    )),
    ("model", LinearSVC(C=0.5, max_iter=2000)),
])

scores_svc = cross_val_score(tfidf_svc, X_train_clean, y_train,
                              cv=cv, scoring="f1_macro")
print(f"TF-IDF + SVC CV F1-macro: {scores_svc.mean():.4f} ± {scores_svc.std():.4f}")

# SGDClassifier is faster for large datasets
tfidf_sgd = Pipeline([
    ("tfidf", TfidfVectorizer(max_features=100000, ngram_range=(1, 2),
                               sublinear_tf=True)),
    ("model", SGDClassifier(loss="modified_huber", alpha=1e-4,
                             random_state=42, max_iter=100)),
])

scores_sgd = cross_val_score(tfidf_sgd, X_train_clean, y_train,
                              cv=cv, scoring="f1_macro")
print(f"TF-IDF + SGD CV F1-macro: {scores_sgd.mean():.4f} ± {scores_sgd.std():.4f}")
```

### Phase 3: Sentence Embeddings as Features

When transformer embeddings are available (e.g., as a pre-computed `.npy` file provided by the organizers, which is common in IOAI to level the compute playing field), treat them as a feature matrix:

```python
# Suppose the organizers provide pre-computed embeddings
# (sentence-transformers or similar, shape: [n_samples, 768])
train_embeddings = np.load("train_embeddings.npy")  # shape: (n_train, 768)
test_embeddings  = np.load("test_embeddings.npy")   # shape: (n_test, 768)

from sklearn.preprocessing import normalize
from sklearn.linear_model import LogisticRegression

# L2-normalize the embeddings (sentence-transformer embeddings are cosine-similarity based)
train_emb_norm = normalize(train_embeddings)
test_emb_norm  = normalize(test_embeddings)

emb_model = LogisticRegression(C=1.0, max_iter=1000, solver="lbfgs")
emb_scores = cross_val_score(emb_model, train_emb_norm, y_train,
                              cv=cv, scoring="f1_macro")
print(f"Embedding + LR CV F1-macro: {emb_scores.mean():.4f} ± {emb_scores.std():.4f}")

# Combine TF-IDF features with embeddings
from scipy.sparse import hstack, csr_matrix

tfidf_vectorizer = TfidfVectorizer(max_features=50000, ngram_range=(1, 2),
                                    sublinear_tf=True)
X_tfidf_train = tfidf_vectorizer.fit_transform(X_train_clean)
X_tfidf_test  = tfidf_vectorizer.transform(X_test_clean)

X_combined_train = hstack([X_tfidf_train, csr_matrix(train_emb_norm)])
X_combined_test  = hstack([X_tfidf_test,  csr_matrix(test_emb_norm)])

combined_model = LogisticRegression(C=0.5, max_iter=1000, solver="saga")
# Note: cross_val on combined requires manual fold handling
# For quick evaluation, use a train-val split
from sklearn.model_selection import train_test_split
Xc_tr, Xc_val, yc_tr, yc_val = train_test_split(
    X_combined_train, y_train, test_size=0.2, stratify=y_train, random_state=42)
combined_model.fit(Xc_tr, yc_tr)
val_preds = combined_model.predict(Xc_val)
print(f"Combined val F1-macro: {f1_score(yc_val, val_preds, average='macro'):.4f}")
```

## Section 4: Computer Vision Task Walkthrough

Image classification appeared in IOAI 2025. Under competition time constraints, training a convolutional neural network from scratch is rarely feasible. The standard approach is to use pretrained features.

### The Transfer Learning Intuition

Pretrained models (ResNet, EfficientNet, VGG) learned rich visual features from millions of images. The early layers detect edges and textures; later layers detect semantic concepts. By treating the output of a pretrained network's second-to-last layer as a feature vector, we get a powerful representation for any image without training a neural network ourselves.

The sklearn-compatible workflow when pre-computed embeddings are provided:

```python
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import normalize
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

# Organizers often provide pre-computed CNN features
# Shape: [n_images, feature_dim] — e.g., ResNet-50 gives 2048-dim features
X_img_train = np.load("train_image_features.npy")  # (n_train, 2048)
X_img_test  = np.load("test_image_features.npy")   # (n_test, 2048)
y_img_train = np.load("train_labels.npy")

print("Feature shape:", X_img_train.shape)
print("Label distribution:", np.bincount(y_img_train.astype(int)))

# L2 normalize CNN features before linear classifiers
X_train_norm = normalize(X_img_train)
X_test_norm  = normalize(X_img_test)

# Logistic Regression on CNN features — very strong baseline
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

img_pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression(C=1.0, max_iter=1000, solver="lbfgs",
                                  multi_class="auto")),
])

scores = cross_val_score(img_pipeline, X_img_train, y_img_train,
                          cv=cv, scoring="f1_macro")
print(f"CNN features + LR CV F1-macro: {scores.mean():.4f} ± {scores.std():.4f}")

# Try Random Forest — captures non-linear feature interactions
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

rf_img = Pipeline([
    ("model", RandomForestClassifier(n_estimators=300, max_features="sqrt",
                                      random_state=42, n_jobs=-1)),
])
scores_rf = cross_val_score(rf_img, X_img_train, y_img_train,
                             cv=cv, scoring="f1_macro")
print(f"CNN features + RF CV F1-macro:   {scores_rf.mean():.4f} ± {scores_rf.std():.4f}")
```

### Handling Raw Images Without Pre-Computed Features

If the competition provides raw image files and you must engineer features yourself:

```python
from sklearn.preprocessing import normalize
import numpy as np

def extract_color_histograms(image_array, bins=32):
    """
    Extract color histogram features from a (H, W, C) image array.
    Returns a 1D feature vector.
    """
    features = []
    for channel in range(image_array.shape[2]):
        hist, _ = np.histogram(image_array[:, :, channel], bins=bins,
                                range=(0, 256))
        features.append(hist / hist.sum())  # normalize
    return np.concatenate(features)

def extract_hog_like_features(image_gray, cell_size=8):
    """
    Simple gradient magnitude histogram (simplified HOG).
    image_gray: (H, W) grayscale array
    """
    gy = np.diff(image_gray.astype(float), axis=0)
    gx = np.diff(image_gray.astype(float), axis=1)
    # Trim to same shape
    gy = gy[:, :-1]
    gx = gx[:-1, :]
    magnitude = np.sqrt(gx**2 + gy**2)
    angle     = np.arctan2(gy, gx)
    
    H, W = magnitude.shape
    features = []
    for i in range(0, H - cell_size, cell_size):
        for j in range(0, W - cell_size, cell_size):
            cell_mag   = magnitude[i:i+cell_size, j:j+cell_size]
            cell_angle = angle[i:i+cell_size, j:j+cell_size]
            hist, _    = np.histogram(cell_angle, bins=9,
                                       range=(-np.pi, np.pi),
                                       weights=cell_mag)
            features.append(hist)
    return np.concatenate(features) if features else np.zeros(81)
```

## Section 5: Time Management and Strategy

IOAI 2025 practical exams are approximately 4–5 hours. Individual competition means no teammate to divide tasks.

### Recommended Time Allocation

For a single practical problem (4 hours):

```
0:00 – 0:15   Read problem statement completely. 
               Note: metric, dataset size, allowed libraries,
               submission format, any provided baseline.
0:15 – 0:40   EDA: shapes, dtypes, missing values, class balance,
               sample inspection (look at actual rows/images/text).
0:40 – 1:10   Baseline pipeline. SUBMIT this immediately.
1:10 – 1:50   Feature engineering or model swapping.
               Re-evaluate with CV. Submit if improved.
1:50 – 2:40   Systematic tuning: try 2-3 models, hyperparameter
               search on best model.
2:40 – 3:20   Ensembling: blend top 2-3 models.
               Evaluate ensemble with CV. Submit.
3:20 – 3:45   Advanced tricks: see Section 6.
3:45 – 4:00   Final submission. Verify format. Make a backup
               submission with the best single model (not ensemble),
               in case the ensemble has a bug.
```

For multiple sub-problems in one session, allocate proportionally and always baseline all problems before tuning any.

### The Backup Submission Rule

Always keep a "safe" submission: a working, slightly-worse-than-optimal solution you are confident is correct. If your final optimized model has a bug and you run out of time to debug, having the backup submission prevents a catastrophic zero.

## Section 6: Advanced Tricks

These techniques provided meaningful score improvements in 2025. Learn them, but apply them only after you have a solid baseline.

### Pseudo-Labeling

If the test set is large and unlabeled, pseudo-labeling can improve performance on self-training:

```python
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import StratifiedKFold, cross_val_score

# Step 1: Train on labeled data
model = RandomForestClassifier(n_estimators=300, random_state=42, n_jobs=-1)
model.fit(X_train, y_train)

# Step 2: Predict on test data with probabilities
test_proba = model.predict_proba(X_test)
test_confidence = test_proba.max(axis=1)

# Step 3: Keep only high-confidence test predictions as pseudo-labels
CONFIDENCE_THRESHOLD = 0.90
mask = test_confidence >= CONFIDENCE_THRESHOLD
X_pseudo = X_test[mask]
y_pseudo = model.predict(X_test)[mask]

print(f"Pseudo-labeled {mask.sum()} / {len(X_test)} test samples")

# Step 4: Retrain on original + pseudo-labeled data
X_combined = np.vstack([X_train, X_pseudo])
y_combined = np.concatenate([y_train, y_pseudo])

model_v2 = RandomForestClassifier(n_estimators=300, random_state=42, n_jobs=-1)
model_v2.fit(X_combined, y_combined)
```

Use pseudo-labeling carefully: if your initial model is weak, pseudo-labels will be noisy and make things worse. Only apply it when your baseline achieves > 80% confidence on test samples.

### Cross-Validation Ensembling (Stacking Out-of-Fold)

Instead of averaging models trained on the full dataset, train each model on 4 folds and predict the 5th (out-of-fold), then use these as features for a meta-learner:

```python
import numpy as np
from sklearn.model_selection import StratifiedKFold
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

def get_oof_predictions(model, X, y, X_test, cv):
    """
    Returns out-of-fold predictions on X and averaged predictions on X_test.
    """
    n_classes = len(np.unique(y))
    oof_preds  = np.zeros((len(X), n_classes))
    test_preds = np.zeros((len(X_test), n_classes))
    
    for fold, (train_idx, val_idx) in enumerate(cv.split(X, y)):
        X_tr, X_val = X[train_idx], X[val_idx]
        y_tr        = y[train_idx]
        
        model.fit(X_tr, y_tr)
        oof_preds[val_idx]  = model.predict_proba(X_val)
        test_preds          += model.predict_proba(X_test) / cv.n_splits
    
    return oof_preds, test_preds

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

# Level 0 models — assume X is already preprocessed
models = [
    RandomForestClassifier(n_estimators=200, random_state=42, n_jobs=-1),
    GradientBoostingClassifier(n_estimators=200, learning_rate=0.05,
                                max_depth=4, random_state=42),
]

# Collect OOF predictions as meta-features
meta_train_parts = []
meta_test_parts  = []

for m in models:
    oof, test_p = get_oof_predictions(m, X_train_prep, y_train,
                                       X_test_prep, cv)
    meta_train_parts.append(oof)
    meta_test_parts.append(test_p)

meta_train = np.hstack(meta_train_parts)
meta_test  = np.hstack(meta_test_parts)

# Level 1 meta-learner
meta_model = LogisticRegression(C=1.0, max_iter=1000)
meta_model.fit(meta_train, y_train)
final_predictions = meta_model.predict(meta_test)
```

### Test-Time Augmentation (TTA) for Tabular Data

For tabular data, TTA means adding small amounts of noise to test features and averaging predictions. This is less common than in CV but can help:

```python
def predict_with_tta(model, X_test, n_augments=10, noise_std=0.01):
    """
    Add small Gaussian noise to numeric features at test time and average.
    """
    all_probas = [model.predict_proba(X_test)]
    for _ in range(n_augments - 1):
        X_noisy = X_test.copy()
        # Add noise only to numeric columns
        X_noisy += np.random.normal(0, noise_std, X_test.shape)
        all_probas.append(model.predict_proba(X_noisy))
    return np.mean(all_probas, axis=0)
```

### Probability Calibration

Some metrics (log loss, Brier score) reward well-calibrated probabilities, not just accurate rankings:

```python
from sklearn.calibration import CalibratedClassifierCV

# Wrap any classifier for probability calibration
base_model = GradientBoostingClassifier(n_estimators=200, random_state=42)
calibrated  = CalibratedClassifierCV(base_model, cv=5, method="isotonic")
calibrated.fit(X_train, y_train)
calibrated_proba = calibrated.predict_proba(X_test)
```

## Section 7: Common Pitfalls in IOAI 2025

### Pitfall 1: Overfitting on the Public Leaderboard

If IOAI uses a split leaderboard (public score on a subset, private score on the rest), optimizing specifically for the public leaderboard is dangerous. Participants who submitted too many times and adjusted their models to the public score often saw their private score drop significantly.

Counter-strategy: trust your local cross-validation score over the public leaderboard. Submit to check your pipeline is working, not to guide feature engineering decisions.

### Pitfall 2: Misreading the Metric

In one reported problem type, the evaluation used a custom weighted F1 where certain classes had 3x the weight of others. Participants who used standard F1-macro left significant points on the table.

Always implement the exact evaluation metric from the problem statement locally:

```python
# Custom weighted metric implementation
def custom_weighted_f1(y_true, y_pred, class_weights):
    """
    Compute weighted F1 where each class has a specified weight.
    class_weights: dict mapping class_label -> weight
    """
    from sklearn.metrics import f1_score
    classes     = sorted(class_weights.keys())
    f1_per_class = f1_score(y_true, y_pred, labels=classes, average=None)
    weights      = np.array([class_weights[c] for c in classes])
    return np.sum(f1_per_class * weights) / np.sum(weights)

# Example usage
class_weights = {0: 1.0, 1: 3.0, 2: 1.5}  # from problem statement
score = custom_weighted_f1(y_val, val_preds, class_weights)
print(f"Custom weighted F1: {score:.4f}")
```

### Pitfall 3: Not Stratifying in CV

Multi-class problems with rare classes — if you have a class with only 15 examples out of 1,000, a non-stratified 5-fold CV may put all 15 in one fold, producing degenerate results for that fold.

Always use `StratifiedKFold` for classification unless you have a specific reason not to.

### Pitfall 4: Wrong Submission Format

A well-trained model gives zero points if the submission file has the wrong column names, wrong ordering, or wrong class labels. Template your submission code early:

```python
# Always inspect the sample submission file before writing your own
sample_sub = pd.read_csv("sample_submission.csv")
print("Sample submission columns:", sample_sub.columns.tolist())
print("Sample submission head:\n", sample_sub.head())
print("Sample submission dtypes:\n", sample_sub.dtypes)
```

## Section 8: The Role of Cross-Validation in Competition Strategy

Cross-validation is not just a way to evaluate your model — in a competition context, it serves multiple purposes:

1. **Model selection**: Which of three candidate models performs best?
2. **Hyperparameter selection**: What value of C in logistic regression works best?
3. **Feature selection**: Does adding this new feature help or hurt?
4. **Ensemble weighting**: Should model A get 60% weight and model B get 40%, or vice versa?

For all these decisions, you need a reliable local CV score. If your CV score and public leaderboard score diverge by more than ~1%, investigate before proceeding.

```python
# Example: using CV to select ensemble weights
from itertools import product

# Suppose you have predictions from two models
proba_rf = ...   # shape (n_val, n_classes)
proba_gb = ...   # shape (n_val, n_classes)

best_w, best_score = 0.5, 0.0
for w in np.arange(0.0, 1.01, 0.05):
    blended = w * proba_rf + (1 - w) * proba_gb
    preds   = np.argmax(blended, axis=1)
    score   = f1_score(y_val, preds, average="macro")
    if score > best_score:
        best_score = score
        best_w     = w
        
print(f"Best RF weight: {best_w:.2f}, F1: {best_score:.4f}")
```

## Section 9: Preparing for IOAI 2026 and Beyond

The trajectory of IOAI suggests that each edition will expand the problem space. Areas likely to become more prominent:

- **Reinforcement learning problems**: Not yet prominent but theoretically on the table
- **Generative model evaluation**: Assessing output quality from a model you are given
- **Multi-modal tasks**: Combining text, image, and tabular data in one problem

For each new area, the same meta-strategy applies: understand the evaluation metric deeply, build a baseline quickly, then iterate systematically.
